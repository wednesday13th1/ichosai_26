# FOLLOW THE WHITE RABBIT — Phase 1

文化祭向けのスマートフォン用カメラ合成体験。HTML / CSS / JavaScript と Three.js、開発・配信用に Vite のみを使用します。

## 起動

Node.js 22以降とpnpmを用意して実行します。

```sh
pnpm install
pnpm dev
```

PCでは表示されたlocalhostを開きます。スマートフォンの実カメラ確認にはHTTPSで配信してください。LANの `http://192.168...` ではカメラは利用できません。`file://` からも起動しないでください。

```sh
pnpm build
pnpm preview
```

`dist/` をHTTPS対応の静的ホスティングに配置し、その公開URLをQRコードにしてください。Sitesの非公開プレビューは所有者確認が入るため、文化祭用QRには匿名アクセスできる公開配信先が必要です。

## 実装済み

- 開始ボタンを押したときのみカメラ権限を要求。背面カメラを優先、音声は要求しません。
- `muted` / `autoplay` / `playsinline` の動画を全画面に表示。
- 透明なThree.jsレイヤーに基本Geometryで白うさぎを生成。外部モデル、画像、CDNへの実行時依存はありません。
- 白うさぎの移動・停止・振り向き。動きを減らす端末設定では跳躍を抑制。
- 権限拒否、カメラ不在、カメラ使用中、HTTPS不足、WebGL障害の案内。
- 終了、ページ離脱、バックグラウンド移行時にカメラを解放。再開は開始ボタンから。
- 映像の録画・保存・送信は実装していません。

1. iPhone Safari / Android ChromeそれぞれでHTTPSのURLを開く。
2. 初回表示では権限要求が出ないことを確認。
3. Enter Wonderland → カメラ許可 → 背面映像、白うさぎ、Follow me...を確認。
4. 権限を拒否し、案内が出ることを確認。サイト設定で許可後に再試行。
5. 縦横回転後も動画とレイヤーが全画面で、うさぎが見えることを確認。

## Phase 1の限界と次の実装

Phase 1時点ではカメラ映像への画面相対の3D合成でした（以下はPhase 1の記録。現在は下記Phase 2を参照）。床・壁の検出、位置追跡、現実空間への固定、人による遮蔽は行いません。スマートフォンを動かしても、白うさぎは現実の同じ位置に留まりません。現在のアニメーションは実際の歩行を促す追跡機能ではありません。

次はPhase 2として、会場導線を決め、iOSも含むマーカー追跡などの方式を選定し、うさぎを現実空間で追う仕組みを追加します。Tiny Door / Portal / 巨大・縮小オブジェクトは未実装です。

## Phase 2 — 白うさぎの追跡（追加実装）

Phase 1の画面相対アニメーションを、相対的な端末方向による探索に更新しました。新規ライブラリはありません。

### 状態遷移

`APPEAR (0.8秒) → WAIT (1.6秒) → RUN (1.6秒) → HIDE (1秒) → REAPPEAR (発見待ち)`

発見すると `Found him!` を0.5秒表示し、2回目まではWAITに戻ります。3回目で `READY_FOR_DOOR` へ進み、中央に寄って停止します。`Something is strange...` は2.5秒だけ表示します。扉はありません。

- RUNは右・左上・右下の順。smoothstepで加減速し、その時の画角の少し外へ移動します。
- REAPPEARは時間経過だけでは終わりません。逃走時から約6度以上向きを変え、うさぎの中心を画面中央の横38%・縦50%の範囲に0.35秒捉えると発見です。
- 端末方向は開始時を基準にします。歩行や場所の移動は不要です。
- iOSで必要な方向センサー権限は、Enterボタンの操作内で要求します。拒否・非対応・センサー停止時はスワイプ案内に切り替わります。カメラ権限は従来通り必要です。
- スワイプ操作はセンサーの代替であり、端末方向による追跡ではありません。
- 画面回転時は現在の見え方を保ってセンサー基準を更新します。バックグラウンドや終了時はカメラと方向入力を停止し、再開時は3回の追跡を最初から開始します。

### 追加・変更ファイル

- `js/interaction.js`: センサー権限、相対方向、縦横回転、スワイプ代替、スクリーン中央判定。
- `js/scenes.js`: 時間ベースのState Machine、3パターン、発見回数、最終状態。
- `js/rabbit.js`: 登場・Idle・逃走・発見時の動作。
- `js/ar.js`: 視線に連動するカメラ、スクリーン座標投影、状態と表示の接続。
- `js/main.js`: 入力とカメラのライフサイクル、状態が変わった時だけUI更新。
- `index.html` / `css/style.css`: 最小限の探索案内・スワイプ対応。
- `tests/chase.test.js`: 自動発見しないこと、短い横切りの除外、3回終了、再開リセット、中央判定。

Phase 3では `#experience` の `rabbitstatechange` イベントを購読できます。`event.detail` は `{ state, completedChases }`。状態は `data-rabbit-state` およびARレイヤーの `rabbitState` getterでも取得できます。

```sh
node --test tests/chase.test.js
pnpm build
```

### スマートフォンでの確認（Phase 2）

1. HTTPSで開きEnterを押し、方向センサー（要求された場合）とカメラを許可。
2. 登場→待機→逃走→消失を確認。そのまま動かさず待ち、勝手に発見にならないことを確認。
3. その場でスマートフォンをゆっくり左右へ向け、再出現したうさぎを中央付近に捉える。
4. 3回発見後、`Something is strange...` と中央停止を確認。
5. 縦横回転・画面ロック・別アプリへの切り替え・×終了と再開を確認。
6. センサー権限を拒否した場合は「画面をスワイプして探してね」が表示され、スワイプで3回完了できることを確認。

実機のiPhone Safari / Android Chromeでのセンサー精度・描画速度・権限ダイアログは別途確認が必要です。相対方向のみによる擬似ARのため、実空間への固定や遮蔽はありません。

- ローカルChromeの模擬カメラと方向イベントで3回発見→READY_FOR_DOOR、終了時のカメラ解放を確認。

## Phase 3 — Tiny Door + Wonderland Portal

Phase 2を3回成功すると、自動的に小さな扉の出現、うさぎの入場、扉の開放へ進みます。扉を中央付近に捉えて見続けると、扉が最大1.65倍までゆっくり拡大し、中の景色が広く見えます。

**Approachは視線保持による疑似演出です。現実の距離・壁・位置は測定していません。** 扉を向けたまま約6秒見続けると発見になります。目を離すと進行は止まり、戻すと再開します。その場で体験でき、歩行は不要です。見かけの扉サイズは仮想スケールであり、現実の30〜50cmを保証するものではありません。

### 追加・変更ファイル

- `js/door.js`: 基本Geometryの小さな扉、真鍮の縁取り、左ヒンジで1.2秒の開閉、出現・拡大演出。
- `js/portal.js`: 独立Wonderlandシーン、開口面だけに表示するRenderTarget、空・キノコ・カード・粒子・奥行き、簡易Portal。
- `js/scenes.js`: Phase 2からの引き継ぎとPhase 3の状態機械。
- `js/interaction.js`: 中央付近での視線保持。Phase 3中はスワイプを使いません。
- `js/ar.js`: 扉とうさぎの配置・入場、Portal描画、開始・終了時のリセット・リソース解放。
- `js/main.js`: 短い案内と状態変更イベント。
- `tests/portal.test.js`: 前段階の完了条件、視線外で進まないこと、発見・リセットの確認。

### Portal方式

WonderlandはメインのThree.jsシーンに追加せず、384×600のRenderTargetに最大30fpsで描画します。そのテクスチャを扉の矩形開口面に貼ることで、景色が開口部の外へ漏れません。視点から開口部を通す非対称透視投影により、向きと疑似Approachで見える景色を変化させます。霧、遠近のキノコ、奥へ細く見える小道で奥行きを表現します。

RenderTargetの作成・描画に失敗した場合は、256×400のCanvasTextureによる簡易の空・キノコ・カード・粒子表示に切り替えます（最大15fps）。簡易版は3Dの視差を省略します。WebGL自体の利用不能・コンテキスト喪失は、従来の終了・再試行案内で扱います。

### 状態機械

`READY_FOR_DOOR → DOOR_APPEARING → RABBIT_ENTERING → DOOR_OPENING → PORTAL_VISIBLE → APPROACHING → PORTAL_DISCOVERED`

- 扉出現1.2秒、うさぎの視線・走行・入場3.6秒、開放1.2秒。
- 中央付近で0.7秒視線を保持後、約5秒のApproach。
- `PORTAL_DISCOVERED` で照明を明るくし、カードを3→7枚、粒子を28→64個に増加。Welcome表示は3秒。
- Phase 3の状態は `#experience.dataset.phaseState` と `phasestatechange` の `event.detail.state` に公開します。Phase 2の `rabbitState` は `READY_FOR_DOOR` を保持します。
- 終了・バックグラウンドからの再開はPhase 1の入口へ戻り、追跡回数とApproachをリセットします。
- Phase 4への移動、写真機能、人間の拡大縮小、空間アンカーは未実装です。

### スマートフォンでの確認

1. HTTPSで開き、カメラと方向センサーを許可。Phase 2の3回追跡を完了。
2. 少し下に扉が現れ、うさぎが振り向いて走り、入口で止まってから消えることを確認。
3. 約1.2秒かけて開き、扉の中だけに空・キノコ・カード・粒子が見えることを確認。
4. 扉にスマートフォンを向けて、その場で約6秒覗く。拡大・視差・Welcome表示を確認。
5. 途中で扉から向きを外し、見ていない間はApproachが進まないことを確認。
6. 縦横回転、×終了、画面ロック、再開を確認。
7. センサーを拒否した場合、Phase 2はスワイプ、Phase 3は正面にある扉を見続けるだけで進むことを確認。

最新のローカルプレビューにPhase 3を反映しています。既存のSites配信URLはPhase 1のままです。
